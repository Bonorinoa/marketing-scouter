### Traces: external vs custom
- **OpenTelemetry SDK (recommended base)**: vendor-neutral spans around fetch → grade → score → draft, with `card_id` and `run_id` as attributes. Near-zero lock-in. The local exporter can write OTLP to a file or to any backend.
- **Langfuse**: best fit for LLM traces (prompt version, tokens, cost per deepseek-v4-flash call) and it ingests OTel. Cloud Hobby is free (low monthly event cap, fine at our volume, but traces leave the box, and they contain public post text). Self-host v3 needs Postgres + ClickHouse + Redis + S3-compatible storage, which is heavy for this VM. **Pick: OTel instrumentation plus Langfuse Cloud free tier for LLM calls only**, with no Wins or personal notes sent (Wins stay local). The hash-chained local events table stays the system of record; Langfuse is a viewer.
- **Custom-only** stays acceptable if Augusto doesn't want any external service. Keep TracePanel either way. It's the user-facing "How this card was made".
- **codebase-memory-mcp**: useful for the agents (indexes the code graph so agents stop re-reading a 2k-line core.py). It's dev-only, never in the runtime path. Adversarial Tester should vet it the same way as sentrux before install. Not verified in this audit.
